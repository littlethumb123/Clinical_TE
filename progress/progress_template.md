# Template Usage Guidelines

## When to Use This Template

Use this template for:
- Daily/weekly progress reports
- Session summaries after significant work
- Bug fix and debugging documentation
- Feature implementation tracking
- Refactoring documentation
- Experiment planning and results

## Section Selection

**Not every section is required.** Select sections based on session type:

### For Bug Fix Sessions:
- Executive Summary
- Bug Fixes & Issues Resolved
- Key Insights
- Files Modified
- Testing & Validation
- Next Steps

### For Feature Implementation:
- Executive Summary
- Session Overview
- Detailed Technical Work
- Decisions Made
- Files Created/Modified
- Testing & Validation
- Next Steps

### For Planning Sessions:
- Executive Summary
- Key Discussions
- Decisions Made
- What Was Resolved vs Unresolved
- Technical Specifications
- Next Steps
- Risk Assessment

### For Experiment Sessions:
- Executive Summary
- Session Overview
- Technical Specifications
- Performance Metrics
- Testing & Validation
- Key Insights
- Next Steps

## Formatting Guidelines

### Status Indicators
- ✅ Complete / Resolved / Passing
- 🔄 In Progress / Ongoing
- 🔲 Pending / Not Started
- ⚠️ Warning / Needs Attention
- ❌ Failed / Blocked
- 💡 Insight / Tip
- 🎯 Goal / Target

- 🐛 Bug
- 📁 File
- 📅 Timeline / Date
- 💬 Discussion

- 🔧 Fix / Implementation
- ✨ Highlight / Conclusion

### Emphasis
- **Bold** for key terms and decisions
- *Italic* for emphasis or technical terms
- `code` for file names, functions, variables

### Checklists
- [x] Completed item
- [ ] Pending item

## Naming Convention

Files should follow this pattern:
```
progress_[Date]_[brief_description].md

Examples:
- progress_Nov12_dataloader_refactor_and_indexing_fixes.md
- progress_Oct25_flash_attention_implementation.md
- progress_Dec15_moe_experiment_results.md
```

## Best Practices

1. **Be Specific:** Include line numbers, file paths, and concrete values
2. **Show Reasoning:** Document not just what was done, but why
3. **Include Code Examples:** Before/after comparisons are valuable
4. **Track Dependencies:** Note which changes affect other components
5. **Quantify When Possible:** Use numbers, percentages, and metrics
6. **Link Context:** Reference related documents and prior sessions
7. **Be Honest About Uncertainty:** Use confidence levels and note unknowns
8. **End with Action:** Always conclude with clear next steps
